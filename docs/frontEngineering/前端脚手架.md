# 前端脚手架

## 2 种方式

* 全局安装 npm 包后，全局可执行命令。例如：eslint

  npm配置 bin 字段，当安装后会自动在环境变量中添加命令 xxx

  ```json
  // package.json
  {
    "name": "cli",  //包名
    "description": "",  //包的描述
    "version": "1.0.0", //包的版本
    "bin":{//配置命令
      "xxx": "./yyy.js" 
    }
  }
  ```

  由于调用的是 JS 文件，一般在第一行执行使用 node 作为解释器

  ```js
  #!/usr/bin/env node
  ```

* 不安装npm包直接执行命令

  例如：使用vite创建项目命令如下

  ````shell
  npm create vite my-project-name
  ````

  这是一种约定的写法，其实际命令如下

  ```shell
  npx create-vite my-project-name
  ```

## 脚手架

### 调试原理

```shell
npm link # 在npm项目根目录下执行，把这个项目作为一个包链接到全局node 的 node_modules下。这就使得本地项目可以不发布而安装在全局使用
npm unlink # 也是在npm项目根目录下执行，把这个项目从全局 node_modules下移除


# ⚠️：npm link 将包安装到全局，可以直接执行 bin字段指定的命令。但是其他项目内安装这个包，还需要下面命令

npm link <package-name> # 在npm项目根目录下执行，将项目的package.json 下的依赖指向package-name这个包。 项目下出现node_module目录
npm unlink <package-name> # 在npm项目根目录下执行，取消链接
```

#### 单包调试

单包：项目根目录包含package.json，是一个npm包项目

创建脚手架项目后，不用发布。注意：**在项目目录下**执行`npm link`，就会自动在node/bin下创建软连接指向项目（只要 node 配置上环境变量了，项目的命令就能在全局执行，相当于-g安装）

这样调试项目时，改动代码，执行脚手架能跟随变化

#### 多包调试

项目下有两个包 abc、bcd-lib。其中abc是实现CLI命令，其依赖bcd-lib导出的函数。如何在不发布 bcd-lib 的情况下，调试abc包？

![image-20241009005120051](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20241009005120DJorfS.png)

```shell
#【 bcd-lib 目录下 】
npm link # 把这个包链接到全局node 的 node_modules下，作为一个包

# package.json
{
  "name": "bcd-lib",
  "version": "1.0.0",
  "main": "lib/index.js" # 导出函数
}

# lib/index.js
module.exports={
    sum(a,b){
        return a+b
    }
}
```

```shell
# 【 abc 目录下 】
npm link # 把自己链接到全局，就可使用bin 下配置的 CLI 命令
# npm i bcd-lib  ⚠️ 直接安装会从官方源查找这个包，肯定找不到。
npm link bcd-lib # 把bcd-lib链接到自己目录下。⚠️abc 下会出现 node_module目录

# 手动到 package.json 中添加依赖
# package.json
{
  "name": "mini-demo",
  "version": "1.0.0",
  "bin": {
    "abc":"bin/abc.js"
  },
  "dependencies": {
    "bcd-lib": "^1.0.0" # 手动添加依赖
  }
}
# bin/abc.js中可以使用未发布的包了
#!/usr/bin/env node
const bcd=require('bcd-lib')
console.log('acb脚本 -->',bcd.sum(1,2))

```

调试完毕发布 bcd-lib后，如何让abc依赖远程包？

```shell
# 【 bcd-lib 目录下 】
npm unlink # 全局取消安装

# 【 abc 目录下 】
rm -rf node_modules
npm unlink bcd-lib # abc项目取消安装 bcd-lib （必须先移除，否则npm i bcd-lib安装不上）

npm i bcd-lib # 远程安装bcd-lib
```

## 三方工具

### minimist

命令行参数解析工具

npm地址：https://www.npmjs.com/package/minimist

**安装**：

```js
yarn add minimist
```

**示例**：

* 代码1：

  ```js
  //index.js
  const minimist = require('minimist')
  const argv=minimist(process.argv)
  console.log(argv);
  
  
  ```

  ```shell
  node index.js --name hedaodao -a 20
  # 输出：
  {
    _: [
      '/Users/yc/.nvm/versions/node/v14.18.3/bin/node',
      '/Users/yc/Documents/test/scaffold/index.js'
    ],
    name: 'hedaodao',
    a: 20
  }
  ```

* 代码2：

  ```js
  //index.js
  const minimist = require('minimist')
  const argv=minimist(process.argv.slice(2)) //process.argv是命令行数组，从索引2开始才是参数
  console.log(argv);
  ```

  执行：

  ```shell
  node index.js project-name --name hedaodao -a 20 #多单词选项需要 --xxx，单字母选项 -x
  
  
  # 输出：{ _: [project-name], name: 'hedaodao', a: 20 }
  ```



**定义文件**

minimist函数的类型定义：

```ts
declare function minimist(args?: string[], opts?: minimist.Opts): minimist.ParsedArgs;
```

可以发现，其接受一个可选的 命令数组、配置选项

```ts
interface Opts {
        /**
         * A string or array of strings argument names to always treat as strings
         */
        string?: string | string[] | undefined;

        /**
         * A boolean, string or array of strings to always treat as booleans. If true will treat
         * all double hyphenated arguments without equals signs as boolean (e.g. affects `--foo`, not `-f` or `--foo=bar`)
         */
        boolean?: boolean | string | string[] | undefined;

        /**
         * An object mapping string names to strings or arrays of string argument names to use as aliases
         */
        alias?: { [key: string]: string | string[] } | undefined;

        /**
         * An object mapping string argument names to default values
         */
        default?: { [key: string]: any } | undefined;

        /**
         * When true, populate argv._ with everything after the first non-option
         */
        stopEarly?: boolean | undefined;

        /**
         * A function which is invoked with a command line parameter not defined in the opts
         * configuration object. If the function returns false, the unknown option is not added to argv
         */
        unknown?: ((arg: string) => boolean) | undefined;

        /**
         * When true, populate argv._ with everything before the -- and argv['--'] with everything after the --.
         * Note that with -- set, parsing for arguments still stops after the `--`.
         */
        '--'?: boolean | undefined;
    }
```



**补充**

* `process.argv` 

  是 Node.js 中的全局变量，它包含了当前进程的命令行参数数组。通常情况下，`process.argv` 数组的前两个元素是 Node.js 的执行路径和主模块文件的路径，而实际的命令行参数从索引 2 开始

* 引入

  ```js
  require('xxxx')(yyy);
  ```

  这种形式说明导入的xxxx包是个函数，yyy是参数



### prompts

命令行交互工具

npm地址：https://www.npmjs.com/package/prompts

**安装**：

```js
yarn add prompts
```

**示例**：

![官网示例](https://github.com/terkelg/prompts/raw/master/media/example.gif)

```js
const prompts = require('prompts');

(async () => {
  const response = await prompts({
    type: 'number', //输入类型
    name: 'value', //返回对象的key
    message: 'How old are you?', //问题
    validate: value => value < 18 ? `Nightclub is 18+ only` : true //校验
  });

  console.log(response); // => { value: 24 }
})();
```

**定义文件**

可见prompts的有两个参数。

* 参数1：对象、数组
* 参数2（可选）：是两个回调函数onSubmit、onCancel

```ts
declare function prompts<T extends string = string>(
    questions: prompts.PromptObject<T> | Array<prompts.PromptObject<T>>,
    options?: prompts.Options
): Promise<prompts.Answers<T>>;
```

参数2的类型定义：

```ts
 interface Options {
   			//提交回调
        onSubmit?: ((prompt: PromptObject, answer: any, answers: any[]) => void) | undefined;
   			//取消的回调
        onCancel?: ((prompt: PromptObject, answers: any) => void) | undefined;
    }
```
