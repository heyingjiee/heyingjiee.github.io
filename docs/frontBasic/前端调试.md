## VSCode调试

### 主流程

1、打开launch.json配置文件。通过配置该文件来定义调试相关的配置

![image-20230722230059104](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230722230059%20.png)

2、在configurations字段中自动添加配置。其主要分为两种模式

![image-20230722230335938](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230722230336%20.png)

* 添加 "Chrome 启动"

  在第三步中启动调试，会启动一个 **调试模式的浏览器** ，同时在该浏览器中打开地址为url的网页

  ```json
  {
      // 使用 IntelliSense 了解相关属性。 
      // 悬停以查看现有属性的描述。
      // 欲了解更多信息，请访问: https://go.microsoft.com/fwlink/?linkid=830387
      "version": "0.2.0",
      "configurations": [
          {
              "name": "Launch Chrome",
              "request": "launch", //启动
              "type": "chrome",
              "url": "http://localhost:8080", //网页地址
              "webRoot": "${workspaceFolder}"
          }  
      ]
  }
  ```

  

* 添加 "Chrome 附加" 

  提前在端口9222启动一个 **调试模式的浏览器** ，配置port字段为浏览器的端口，启动调试后就能看到在这个浏览器中所有的网页信息 

  ```json
  {
      // 使用 IntelliSense 了解相关属性。 
      // 悬停以查看现有属性的描述。
      // 欲了解更多信息，请访问: https://go.microsoft.com/fwlink/?linkid=830387
      "version": "0.2.0",
      "configurations": [
          {
              "name": "Attach to Chrome",
              "port": 9222,
              "request": "attach", //附加
              "type": "chrome",
              "webRoot": "${workspaceFolder}"
          }   
      ]
  }
  ```



3、启动调试

### Chrome 附加

启动**调试模式的浏览器**

```shell
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --user-data-dir=你自己创建的某个目录

# /Applications/Google Chrome.app/Contents/MacOS/Google Chrome 是mac上chrome软件做在位置

# 其中的 '\ ' 是为了转义空格

# --remote-debugging-port 启动调试的端口

# --user-data-dir 调试时使用的浏览器数据存储目录
```

### Chrome 启动

与Attach不同，这种方式启动调试时，会自动启动**调试浏览器**，不必再手动启动了

所有，后面的所有调试都是基于这种方式

```json
{
    // 使用 IntelliSense 了解相关属性。 
    // 悬停以查看现有属性的描述。
    // 欲了解更多信息，请访问: https://go.microsoft.com/fwlink/?linkid=830387
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Launch Chrome",
            "request": "launch", //启动
            "type": "chrome",
            "url": "http://localhost:8080", //网页地址
            "webRoot": "${workspaceFolder}"
        }  
    ]
}
```



### 配置文件配置项目

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Launch Chrome",
            "request": "launch",
            "type": "chrome",
            "url": "http://localhost:8080/charge-attract-customer-platform", //网页服务器的地址（本地开发一般就是devServer的地址）
            "runtimeExecutable":"dev", //指定使用浏览器的版本，默认stable。可以去官网安装dev版本https://www.google.cn/intl/zh-CN/chrome/dev/
            "userDataDir": false, //false是使用浏览器默认的数据存储目录，特别注意浏览器目录同时只能被一个实例访问，设置false时，要保证浏览器必须只能打开一个。也可以手动指定存储数据的目录。注意：false使用默认目录时，浏览器中安装的插件、历史记录才会存在
            "runtimeArgs": [
                "--auto-open-devtools-for-tabs", //启动浏览器时，打开调试器
                // "--incognito" //浏览器使用无痕模式
            ],
            "sourceMaps": true,  //浏览器开启sourceMaps
            "webRoot": "${workspaceFolder}"
        },
      
    ]
}
```



补充

* 推荐安装[dev版本](https://www.google.cn/intl/zh-CN/chrome/dev/)

  启动多个浏览器时，再设置使用默认数据存储目录，则会报错。必须关闭所有浏览器实例

  ```js
  "userDataDir": false //使用浏览器默认数据存储目录
  ```

  ![image-20230723001317278](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723001317%20.png)

  

  安装Dev版本，这样可以调试时使用游览器默认数据存储目录，就不会和稳定版本冲突导致出现上面的报错。而且，只要设置使用dev的用户数据存储目录，那么在dev版本安装的插件都可以正常使用

  ```json
  "runtimeExecutable":"dev" //使用dev版本
  ```

  




## 调试框架


sourceMaps与sourceMapPathOverrides

  ```json
  //开启"浏览器"的sourcemap功能。 
  //即建立 编译后的源码 与  源码 的映射
  "sourceMaps": true 
  
  
  //设置 源码 与 本地文件 的映射 （下面三个是默认的）
  "sourceMapPathOverrides":{
                  "meteor://💻app/*": "${workspaceFolder}/*",
                  "webpack:///./~/*": "${workspaceFolder}/node_modules/*",
                  "webpack://?:*/*": "${workspaceFolder}/*"
              }
  ```



 浏览器实际运行文件（编译后的文件）

  ```text
  webpack-internal:///node_modules/babel-loader/lib/index.js??clonedRuleSet-40.use[0]!./node_modules/@vue/vue-loader-v15/lib/index.js??vue-loader-options!./src/views/login.vue?vue&type=script&lang=js&
  ```

  开启sourceMaps浏览器控制台显示的文件

  ```
  webpack://inquire/src/views/login.vue?01f7
  ```

  本地项目文件

  ```
  login.vue
  ```

###  调试Vue

对于Vue项目来说，浏览器实际运行的是编译后的代码。开启sourceMaps选项后，可以看到浏览器的控制台显示的是编译前的源码码。

![image-20230723011054385](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723011054%20.png)

浏览器找到了编译前代码的位置，而VSCode呢？

VSCode自动打开了一个 `login.vue?01f7`的文件，因为而不是实际的`login.vue`文件，所以VSCode提示了不可编辑该文件

![image-20230723011427760](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723011428%20.png)

这主要是因为Vue自动生成的source map文件导致，浏览器找到的文件名后拼接了 `?hash`，进而VSCode真的去尝试在本地打开这个文件

```
login.vue?01f7
```



如何解决？本质上来说只要我们能去掉`?hash`就可以了

* vue/cli创建的项目，在vue.config.vue中配置[devtool选项](https://webpack.docschina.org/configuration/devtool/)

  此选项控制是否生成，以及如何生成 source map。

  ![image-20230723014332503](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723014332%20.png)

  修改后，从新运行即可发现映射到了正确的文件名

  ![image-20230723014808433](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723014808%20.png)

  在增加一条，添加浏览器的源码到本地文件的映射即可

  ```json
  "sourceMapPathOverrides": {
     "webpack://inquire/src/*":"${workspaceFolder}/src/*" 
  }
  ```

  也可以用`?:`做占位符

  ```json
  "sourceMapPathOverrides": {
     "webpack://?:/src/*":"${workspaceFolder}/src/*" 
  }
  ```

  启动调试，可以看到成功映射到了本地的login.vue

  ![image-20230723110921997](https://hedaodao-1256075778.cos.ap-beijing.myqcloud.com/Essay/20230723110922%20.png)
